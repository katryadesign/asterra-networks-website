Wireframe documentation — Inquiry screen

Screen: Inquiry screen · state: error, node sErr. Exit: retry “Retry?”, send the request again. Typed values remain visible: flows.md calls this the most expensive dead end in the model, a qualified lead lost to a form failure. · flow nodes: inquiry, sending, sErr, success · jobs: MAIN end state; R4 caught by the role and request-type field, including reseller and partnership; E1 in the routing promise, the answering specialist speaks the buyer's vocabulary · states: success, error, loading. The only screen in the main flow with a confirmed success state.

Single step by rule (brief §6): no multi-step wizard, no gate. Fields per sitemap.md O7: name, company, contact, industry, solution of interest pre-filled from context, role or request type, message. The form submits to the success page so the happy path can be walked by click; real behaviour is asynchronous and belongs to the build stage.

Context (Asterra Shield · Maritime) sits above the form as a permanent zone: it is what "with context passed" means, and the same values appear in the success receipt.

Anti-patterns avoided (sitemap.md O7): a contact page with no form at all, an off-domain form, a label that does not match the action. The button says what it does.

Error keeps the typed values visible: flows.md calls this dead end the most expensive in the model, a qualified lead lost to a form failure.
