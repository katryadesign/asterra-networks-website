# Спільний бриф для екранних агентів — лейаут зі змістом

## Залізні правила
1. **Розмітку і текст HTML не чіпати взагалі.** Тільки CSS у свій файл `_parts/<screen>.css`.
2. **Спільні файли не редагувати**: `_wireframe.css`, `_panel.css`, чужі фрагменти — read-only.
3. **Скоуп кожного правила** — тільки свій екран: через `body:has(.wf-states a[href^="<screen>"])`
   або унікальні класи/id екрана. Правило, що зачепить чужий екран, — брак.
4. **Жодних анімацій** (вето користувача; transition теж не додавати). **Жодного sticky.**
   **Жодних світлих блоків** (вето: темна тема тримається тональними зсувами).
5. **Кожен блок правил** починається коментарем: яка робота екрана і який елемент змісту
   вмотивували прийом. Прийом без робочої мотивації НЕ додається — «динамічність заради
   динамічності» заборонена прямо.
6. Заборонені патерни: бічні кольорові смуги >1px, gradient text, надзаголовки-eyebrow над
   кожною секцією, однакові картки-сітки, тіні. Іконки — тільки Solar linear через
   api.iconify.design, маскою, з наявного набору сторінки.

## Токени (з _panel.css, не перевизначати)
--bg 0.12 · --surface 0.17 · --surface-2 0.21 · --line 0.30 · --line-strong 0.42 ·
--ink 0.97 · --ink-2 0.78 · --ink-3 0.64 (усі oklch, chroma 0) ·
--signal oklch(0.68 0.19 25) — ТІЛЬКИ подія (строк/збій), нікуди більше ·
--r 2px · шрифти: --font-sans (Familjen Grotesk) / --font-mono (JetBrains Mono, тільки величини й коди) ·
підлога кегля 0.8rem=12.8px · контраст: текст ≥4.5:1, великий ≥3:1 (перевіряй парою fg/bg).

## Що вже дає спільний шар (_panel.css) — не дублювати
- Рейкова сітка `.stack-s > section` із зиґзаґом сторін (парні секції дзеркалять).
- Смуги-підкладки var(--surface) для секцій із `table.spec`, `.trio-l`, `.rows`.
- Фото-герой через `.gm-head .wrap::after` на guided-matching / solution-detail /
  industry / crew-access (по ідентичності екрана зі смуги станів).
- Бенто `.rows` (перший ряд на всю ширину), панелі `.reg-row`, `.kv`, `.trio-l > div`.
- Кнопки/бейджі/стани — готова мова, не перевизначати.

## Формат результату
Файл `wireframes/_parts/<screen>.css` + фінальний текст-звіт: перелік прийомів у форматі
«прийом → який елемент/робота його вимагає». Якщо для екрана правильніше НІЧОГО не додати —
так і написати (це легітимний результат, особливо для гігієнічних сторінок).
