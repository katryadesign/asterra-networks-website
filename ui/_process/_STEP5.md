# Крок 5 — протокол переводу екрана на кіт (для субагентів)

Робочий файл уроку 07. Еталон виконання — уже переведені `wireframes/entry.html`,
`guided-matching*.html`, `industry*.html`, `solution-detail*.html`: відкрий один із них
і подивись, як виглядає результат.

## Мета

Кожна сторінка групи підключає **тільки** кіт і службовий хром:

```html
<link rel="stylesheet" href="../ui/kit.css">
<link rel="stylesheet" href="_chrome.css">
```

і виглядає **рівно так само, як до переводу** (перевіряє скрипт звірки, не око).

## Правила

1. **Копій не робити.** Змінюється сам файл `wireframes/<page>.html`.
2. **Структура і текст — з вайрфрейма.** Не додавати, не видаляти й не переставляти
   елементи в `<main>`; не змінювати жодного слова. Міняються **тільки атрибути `class`**
   (і посилання на стилі). Виняток — оболонка, пункт 4.
3. **Жодного стилю на екрані:** ні `<style>`, ні `style=""`.
4. **Оболонка:** блок `<header>…</header>` замінити на `<header class="site-header">…</header>`
   з `ui/shell.html`, блок `<footer>…</footer>` — на `<footer class="site-footer">…</footer>`
   звідти ж. Дослівно, без змін. `aria-current` не ставити.
5. **Вигляд — тільки з класів кіта.** Спершу використай наявні класи (таблиця «старе → кіт»
   у `ui/inventory.md` §13 і шапка `ui/kit.css`). Якщо бракує — **нове спершу в кіт**:
   - додай клас у `ui/kit.css` **тільки всередині секції своєї групи**
     (`/* ═══ ГРУПА … */ … /* ── кінець групи <id> ── */`);
   - **наявні правила кіта поза своєю секцією не змінювати** — від них залежать уже
     переведені екрани. Треба інакше — зроби варіант (`.x--щось`) у своїй секції;
   - **усі значення — через змінні:** оголоси їх у своїй секції на селекторі `:root`
     (`:root { --<компонент>-<властивість>: …; }`), у класах — тільки `var(--…)`. Голі числа
     дозволені лише в умовах `@media`;
   - покажи новий клас у вітрині `ui/kit.html` між коментарями своєї групи (тексти —
     дослівно з вайрфреймів);
   - додай рядок у `ui/inventory.md` §15 під своєю групою: «клас · екрани · навіщо».
6. **Спільні файли `ui/kit.css`, `ui/kit.html`, `ui/inventory.md` редагувати ТІЛЬКИ
   інструментом Edit** (не скриптами, не Write): паралельно працюють інші агенти. Якщо Edit
   відмовив через зміну файлу — перечитай і повтори. Не чіпай `_chrome.css`, `_panel.css`,
   `_wireframe.css`, `_parts/*`, `shell.html` і сторінки інших груп.
7. **Значення бери з реального рендеру еталона**, не з наміру в CSS. Каскад еталона:
   `_wireframe.css` → `_panel.css` → `_parts/<screen>.css`. Відомі пастки:
   - правила `body > header` / `body > footer` у еталоні **не спрацьовують** (оболонка лежить
     у `.wf-page`) — кіт це вже повторює, нічого не роби;
   - правила скоупу `body:has(.wf-states a[href^="<screen>"])` і
     `body:has(a[aria-current][href^="<screen>"])` у `_panel.css` — це екранні правила;
     у кіті вони стають явними варіантами;
   - стан (`error/empty/loading/success`) у еталоні вгадувався через `:has()`; у кіті його
     називає клас (`.notice--error` тощо).
