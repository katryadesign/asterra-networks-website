Information Architecture

The IA derived from jobs, not from the B2B template: an entity inventory → 8 job-backed screens → a 5-item navigation model → 4 user flows with states and dead ends → a job × screen traceability matrix. Orphans and hypotheses are kept visible, not hidden.

Sources: sitemap.md · flows.md · jtbd.md · personas.md Compiled: 2026-08-05
Standing caveat: every structure below inherits the site-visit bet (jtbd.md §6) — purchase triggers are documented, visit triggers are not. This is designed support, not observed behaviour. Markers: [?] hypothesis · [ORPHAN] no confirmed job.
Sitemap Navigation Flows Traceability

Sitemap — screens grouped by user logic

Each screen exists because a job needs a way to act on an entity (sitemap.md §5). Jobs are labeled per screen; groups appear only where jobs confirm them. One expected group — “compare the options” — is deliberately absent: demand for comparison is recorded nowhere (jtbd.md §6, §8.3).

ORIENT — “which solution fits us?”

Job cluster: MAIN

Entry screen
MAIN — start P1 + P2/P4 GLOBAL · site root O3 Industry + O4 Situation

The shop-window of the buyer’s own objects: industries, situations, dated norms. The five-pillar list lives here as a section (a standalone overview screen failed verification). Exploration only — no quote CTA (brief §6).

Guided matching screen
MAIN R1 (norm entry) P1 + P2 GLOBAL · item 1 O4 → O1

Situation → recommended solution; asks about the trigger, not the technology. [?] its lead over recognition entry rests on the untested “no specialist across five pillars” thesis (personas.md §8.4).

Industry screen · one per industry, Maritime leads
MAIN — self-id E1 language S1 (Maritime) P1 ⭐ / P4 GLOBAL · item 2 O3

Discovery by recognition; Maritime carries the crew-retention argument natively. [?] industry-vs-situation lead is open (research.md §10.6).

UNDERSTAND FIT — “is this it, and will it survive scrutiny?”

Job cluster: MAIN · R1 · R2 · R5

Solution detail screen · one per solution
MAIN R2 proof R3 forwardable R1 norms closed P1 + P2 CONTEXTUAL O1 + O5

The forwardable core object of the site. Proof (named body, single-source numbers) is an attribute here — R2 is deliberately screen-less. Reached via matching, industry, norm, or the entry pillar section.

Crew access & control screen
R5 S1 hiring R1 MLC P1 ⭐ + P4 GLOBAL · item 4 O8

The rule set sold at message level: quotas, ranks, filters, geo, backup channel, cost visibility. The altitude bet — nobody in the market leads with this (jtbd.md §8.2.3).

Norm screen · one per dated norm
R1 R2 via paper P1 + P2 GLOBAL · item 3 O2

Norm → which solution closes it → what paper you get. The unclaimed vendor-side link. [?] that buyers bring the norm question to a supplier at all (jtbd.md §3 R1).

VERIFY THE PROVIDER — deliberately not a screen

Job cluster: R2 (table stakes)

R2 is served by O5 Proof Items distributed as attributes on solution, industry and crew screens under the E2 single-source constraint. A standalone “trust page” would detach proof from the object it proves.

PREPARE INTERNAL APPROVAL — “it must survive whoever pays”

Job cluster: R3 · E2

Approval materials screen [?]
R3 E2 constraint P2 → P4 (P1 = 2) DEEP O6

Ungated library of forwardable, dated, self-consistent artifacts. Hypothesis: R3’s primary carrier is the forwardable solution page; contents are undefined (personas.md §7.4). Rises if the primary flips to P2. Onward path → Inquiry.

REACH THE EXPERT — the end state of the main job

Job cluster: MAIN · R4

Inquiry screen
MAIN — end state R4 role field E1 routing P1 ⭐ + P2/P4 GLOBAL · item 5 O7

Single-step request carrying solution + industry context, the role field (catches frame agreements early) and the routing promise. Every flow terminates here — its error/retry loop is the single highest-leverage state in the model.

Depth to the main job — 3 transitions (canonical path)

Entry screen →MAIN: orientation Guided matching →MAIN: matched Solution detail →MAIN end · R4 Inquiry

Fit rationale and reliability proof cost 0 extra transitions — both live on the Solution detail screen (the “R2 screen-less” decision). Alternative paths: via Industry — 3 · via Norm — 3 · crew trigger — 2 (Entry → Crew → Inquiry). Excluded from counting: scroll, menu, tabs, accordions.

User flows

One flow per job, headed by the verbatim jtbd.md phrasing. Rectangles are §5 screens; diamonds are decisions; stadium nodes are states (loading / empty / error / success); circles are dead ends. Policy: recoverable situations offer a forward branch before terminating; trust collapses terminate without one.
Color legend: green, thick — the happy path · blue — legitimate alternative paths and detours · amber — recovery branches and empty/error states · red — dead ends. Loading states are dashed grey; success states are green-filled.
